# Module notes

These notes describe each proof module and state what it leaves unproved. The [README](../README.md) lists the headline results and explains how to run the checks. File names refer to `verification/`.

The proof work is partial. It does not prove the three Sapling contracts, their external calls, or the Octez protocol. Run `inventory.py` to list the instruction nodes that still need semantics.

`check_order.py` pins and parses the five scripts through Octez, checks the relevant source AST, generates Coq statements, runs `coqc`, prints the assumptions and runs `coqchk`. Its source shape gates for the FA2 reversal fragments, the FA1.2 final merge and the ticket identity guard run before any Coq is generated; the mutation checks rely on them. The parser, translation and modeled instruction meanings, including READ_TICKET and the comparator, remain trusted assumptions. `coqchk` rechecks proof objects; it does not establish their connection to Octez.

`FA2LoopBody.v` proves the modeled successful positive-balance path, and `FA2DepositBody.v` proves modeled negative and zero branches after their shared verification prefix, all under explicit primitive frame equations. `FA2Environment.v` supplies one callback dispatch for both paths; its callbacks do not themselves establish protocol semantics. `translate_fa2_canonical.py` translates the complete parsed FA2 transaction-loop body and `check_order.py` checks its Coq term equals `FA2Combined.canonical_iteration`. This includes both branches and uses six named primitive interfaces. The translator, its type erasure and its Michelson correspondence remain trusted; equality only checks the resulting terms. The positive proof covers successful verification, decoding and a 28-byte re-encoding. The callback semantics and failure behavior of complete batches remain separate obligations; the negative and zero successful iterations are composed with the common prefix.

`LoopInduction.v` proves a failure-aware iteration theorem for arbitrary list length at fixed structural fuel. Its premise requires a separate per-transaction refinement proof for every relevant state and input; the theorem does not supply that premise or prove a batch invariant. The successful-trace results below cover operation construction under their premises; unconditional loop behavior, rejected batches and external execution remain unproved.

`FA2MixedBatch.v` proves an arbitrary-length successful mixed trace: each positive result prepends the decoded withdrawal, each negative result invokes the map update callback with the fixed sender and the prior lookup plus the absolute balance, and a zero result changes neither public accumulator. Its proof composes the actual canonical body at fixed structural fuel, without bounding the list length. The trace explicitly requires each abstract verification to succeed and each branch's input guard to pass. It does not prove rejected executions, output-operation construction, token transfers or collateral.

`FA2PrivateSuccess.v` composes the entire modeled FA2 program for successful traces ending with an empty public map and withdrawal list; its returned operation list is empty. The entire parsed FA2 program matches this model when parameterized by its exact parsed public arm. That theorem does not execute the public arm; the separate `FA2PublicSuccess.v` theorem covers its modeled successful construction. The map update callback is arbitrary, so the final-empty premise alone does not establish that no deposits occurred or that collateral is safe. An all-zero trace specialization avoids map-update laws entirely.

`FA2PublicSuccess.v` composes the whole modeled FA2 program for successful mixed traces that produce nonempty public transfers. Given the stated final map/withdrawal shape, successful typed lookup and explicit AMOUNT, SELF_ADDRESS and TRANSFER_TOKENS frame equations, its output is one modeled transfer operation containing supplied-order deposits before the transaction-order withdrawal group. The separate private-output theorem handles successful traces with empty public accumulators. `FA2SenderMap.v` provides a concrete empty/single-sender map callback model and proves that, on counted successful traces, the final sender amount equals the initial amount plus the sum of negative-balance deposit magnitudes. It does not establish Octez map refinement, a converse for every execution, token-ledger behavior, rollback, or cryptographic backing.

The separate `FA2StepInverse.v`, `FA2FullExtract.v`, `FA2TraceShape.v`, `FA2FullInverse.v`, `FA2OutputInverse.v` and `FA2ParsedInverse.v` prove the converse for successful complete modeled calls using that concrete single-sender dispatcher. They derive zero tez, mixed and counted traces, the reachable empty/single-sender map and its deposit sum, withdrawal shape, and either an empty private output or the exact ordered public transfer. Public lookup success is derived. No successful trace, final shape, guard result or desired output is assumed. Complete context/lookup/transfer specifications and byte-valued Sapling bound data remain premises. This does not prove the map, VM or encoding specifications refine Octez, or connect deferred operations to concrete assets, liability or rollback.

`FA2Boundary.v` proves the modeled zero-tez check, initial stack construction and private-only return path; `FA2Operations.v` proves the exact deposit-group loop body constructs one payer-to-pool group per supplied map entry, for arbitrary entry-list length, in reverse supplied order. The checker matches each proof program to the corresponding parsed source. SELF_ADDRESS and AMOUNT are framed callbacks. Protocol refinement, correspondence of the reachable map model and external token execution remain open. `FA2PublicSuccess.v` supplies the whole successful construction described above.

`FA12LoopBody.v` proves successful positive, negative and zero modeled transaction iterations under explicit Sapling, encoding, sender, self-address and operation-construction frame equations. The parsed FA1.2 loop matches that program. `FA12MixedBatch.v` composes these steps for arbitrarily long successful traces, preserving separate reversed deposit and withdrawal operation lists. These results rely on the stated primitive frame equations and trace hypotheses; source translation and Octez correspondence remain trusted. The whole-program result for FA1.2 is the converse described next.

`FA12AddressGuardInverse.v`, `FA12LoopExtract.v`, `FA12StepInverse.v` and `FA12FullInverse.v` prove the converse direction for complete modeled FA1.2 calls on the specified input stack. Any successful execution yields zero attached tez, a successful contract lookup, a valid mixed trace and the exact updated storage and deposit-before-withdrawal operations. The theorem assumes complete Some/None primitive equations and byte-valued Sapling bound data; it does not assume a successful trace or the desired output. `FA12ParsedInverse.v` connects that result to the generated, kernel-checked whole parsed program equality. This closes the modeled FA1.2 trace-extraction gap, while typed protocol correspondence, cryptographic backing and external operation execution remain open.

`TicketWithdrawal.v` proves modeled partial and exact withdrawals, plus rejection for insufficient held quantity, under explicit unpack, contract lookup, split and transfer-construction frame equations. The parsed positive withdrawal branch matches that program. It does not prove stored-ticket identity, full ticket-pool control flow or execution of the resulting operation. `TicketLoopBody.v` additionally models the complete parsed transaction body and proves successful nonpositive credit consumption, partial and full positive withdrawals, and rejection of excess credit consumption under explicit callbacks. `TicketMixedBatch.v` composes the successful paths as described below.

`TicketMixedBatch.v` composes source-shaped successful ticket transactions over arbitrary batch lengths and proves the balance equation `initial held quantity - initial received credit - sum of Sapling balances = final held quantity - final received credit`. Its premises include successful branch guards and explicit primitive frame equations. The quantity function maps absent or malformed modeled values to zero; well-typed ticket identity, initial credit/holding correctness, final credit zero, cryptographic liability and operation execution require separate arguments. The checker connects this result to the exact parsed transaction loop.

`TicketFinal.v` executes the parsed final credit guard and return path: zero remaining credit returns the reversed operation list and unchanged modeled held-asset storage, while positive remaining credit fails. `TicketPostBatch.v` composes the successful arbitrary-length ticket loop with that final path and the credit-adjusted accounting equation. The valid-identity initialization is covered by the separate `TicketInit.v` theorem; establishment from arbitrary malformed inputs, failure paths outside the named lemmas, protocol correspondence and external operation execution remain unproved.

`FA2Map.v` and `FA2MapFuel.v` prove arbitrary-length execution of the parsed withdrawal MAP body, preserving each recipient and amount in order while inserting the stored token id. This is a modeled instruction result, not the surrounding transfer operation or token-ledger execution.

`TicketInit.v` models the complete initialization with old and received optional tickets of the same fixed asset identity and proves that joined quantity equals old quantity plus incoming credit. `TicketCompleteSuccess.v` composes initialization, arbitrary successful ticket-loop traces and final output for traces ending in zero credit. It proves `old held quantity - sum of Sapling balances = final held quantity` and returned operation order. Its premises include zero tez, valid fixed-identity tickets, successful joins/verification/guards, callback frame equations and the trusted translator; it does not prove typed-ticket validity, all failures, Sapling liability or operation execution.

`TicketInitInverse.v`, `TicketStepInverse.v`, `TicketPostInverse.v`, `TicketFullInverse.v` and `TicketParsedInverse.v` prove the whole modeled ticket-call converse. From success on arbitrary optional typed-shape input tickets, they derive zero tez, matching configured identities for both stored and paid tickets, a valid arbitrary-length trace ending with exactly zero received credit, the exact ordered output and fixed identity, and `old held quantity - sum of public balances = final held quantity`. No matching identity, successful trace, zero final credit or output is assumed. Complete comparison, join, verification, decoding, receiver, split and operation specifications remain premises. Positive quantities, valid comparable/address types, linear ownership, protocol correspondence, cryptographic liability and external execution remain outside this result; the untyped model also admits zero-quantity ticket shapes that native typing excludes.

`TicketPrimitives.v` models READ_TICKET and positive-amount JOIN/SPLIT field behavior and proves split/join facts. These are model-level theorems, not a proof of the ticket-pool control flow, linear ticket ownership, or a refinement to Octez.

`AdapterRoute.v` proves construction and storage return for the exact parsed post-guard suffixes. `AdapterAuthorization.v` extends this to an exact characterization of each complete modeled adapter call, including all rejection branches. Successful ingress implies zero tez, an unused route, issuer sender, full ticket identity, successful pool lookup and exactly the stored proof and pool destination, with used=true. Successful egress implies zero tez, 28-byte beneficiary encoding, pool sender, full identity, successful issuer lookup and exactly the immutable beneficiary route and unchanged configuration. `AdapterParsedInverse.v` rewrites the complete parsed-program equalities before applying those converses. No guard success or desired output is assumed. Complete primitive frame equations, comparison equality and the partial VM remain specifications without a proved typed Octez correspondence. Address-to-code/storage binding, ticket ownership and downstream execution remain open. The adapter source pins correspond to commit `12f4c84f81d68697e80b49fd02507468fb465889`; two type-correct selector/used-flag mutants test the source gates.

`check_mutation.py` creates temporary, type-correct FA1.2, FA2 and ticket source mutations, confirms their typechecking, and requires the corresponding AST check to reject each mutant for its intended reason. This is change detection, not a proof of mutant execution. `verify.py` runs the checked proofs, mutations and checked proofs again without modifying the source contracts.

Each successful baseline run copies its exact generated Coq source files, checked proof objects and a manifest into a newly created unique directory under `.local/verification/` at the repository root, which Git ignores. The manifest records source and canonical parsed-JSON hashes, client/Coq binary hashes and version outputs, and the mockup head's protocol metadata. Use `--artifacts-dir /some/directory` to choose a different parent; the runner creates a new child and does not overwrite existing runs. A source hash mismatch is a deliberate hard stop requiring review; do not update the expected hashes without examining source and proof coverage. Typed source-to-model correspondence, the protocol-to-model execution bridge, concrete asset/Sapling liability and external call-tree composition remain open work.

`FullVM_WIP.v` is a partial, untyped interpreter with structurally recursive ITER and MAP over arbitrary-length lists. Complete parsed programs for the three pools are translated and matched to the proof programs; the translation remains trusted. Its instruction semantics and explicit primitive callbacks have no proved typed correspondence to Michelson or Octez. Whole modeled success theorems and all three pool converses therefore do not constitute complete protocol or custody verification.

`InternalQueue.v` proves the source-shaped internal-operation dispatcher executes an operation's descendants before its siblings, preserves the remaining dispatcher budget across that split, and records each executed nonce exactly once. The budget counts dispatches rather than gas. Its pending-operation induction permits temporary unsettled liabilities; it requires a separate step-preservation proof.

`ManagerBatch.v` extends that control-flow model across root contract execution, its internal operation tree, late storage-fee checks and subsequent manager operations. A failed root, descendant or late fee check restores the manager-list snapshot, including earlier root storage changes. The snapshot follows upfront fee collection. An explicit fee-frame law is needed to relate its asset projection to the earlier context; fees are not refunded. `QueueExamples.v` checks descendants-before-siblings, failures after earlier effects, nonce replay across roots, root-storage rollback and late fee failure. These are kernel-checked control-flow models and examples. No proof yet connects their context, operation or fee callbacks to `apply.ml`, so they do not establish actual Octez atomicity.

`MichelineRaw.v` retains primitive names, arguments, annotations and scalar text in a raw tree and decodes an arity-tagged prefix stream. `translate_micheline_raw.py` produces both representations from the exact fresh, pinned AST snapshots already parsed by the runner. The generated `MichelinePrograms.v` checks complete tree/stream equality for all five programs, including their declarations. The Python importer and JSON/parser boundary remain trusted; generating both expected trees and streams is not an independent parser proof. Unsupported non-ASCII scalar text is rejected explicitly rather than altered.

`TypeInferenceWIP.v` computes connected stack transitions through all five complete decoded bodies, including branches and arbitrary-length list/map iteration at the type level. It links each input and output stack to the source parameter/storage declarations after annotation-erasing tuple normalization. It selects `COMPARE` by stack type and rejects ticket duplication. The results use no external per-instruction type-map hints. This restricted checker is not yet proved sound against Michelson's typing rules: position-specific passable/storable/packable checks, annotation validity/normalization, typed execution and erasure to `FullVM_WIP` remain unproved. Native acceptance of the five particular sources does not establish that correspondence. The runner compiles and kernel-checks these computed equalities without presenting them as native typing theorems.

`SaplingNotes.v` introduces a separate ghost set of live notes. A transaction witness consumes existing notes, retains the remainder and creates fresh notes, with consumed value minus created value equal to the public balance. Liability change and the withdrawal upper bound follow from that witness. Its cryptographic/context soundness premise mentions no reserve or backing conclusion. The sign follows pinned `lib_sapling/core_sig.ml:244`, `forge.ml:203` and the balance returned by `sapling_validator.ml`, rather than conflicting reference prose.

`AssetLedger.v` defines concrete per-account debit-then-credit movements and decodes the FA1.2 and FA2 parameters, checking the configured operation handle and token id. It proves actual reserve deltas, including zero effect for self transfers, and a conditional honest-issuer trace theorem. Mathematical ledger functions grant no authorization or spendability. The chosen issuer must satisfy exact-transfer projection, funding and custody-policy requirements.

`PoolCollateral.v` derives emitted movement bounds from the source-model FA1.2 mixed trace and FA2 reachable sender-map/counting trace. It proves net emitted reserve delta is at least the live-note liability increase. The ticket result separately combines note accounting with the source-derived final-zero-credit quantity equation, then bounds actual inventory from a certified same-ticketer/full-contents stored fragment. Native ticket validity, ownership and storage/context correspondence remain open.

`CollateralCallTree.v` instantiates the queue and manager model with `actual reserve + queued movement delta - live-note liability`. Its entry certificates contain source traces, note witnesses, output shapes and decoded transfers, rather than a backing inequality. Issuer settlement replaces a pending movement with its real ledger effect; source-certified reentrant pool calls use the same derived liability bound. An empty committed queue is backed if the initial state was backed and every successful root/internal call meets the stated issuer, source-pool or framed-call classification. FA2 private calls can change notes without changing total liability. These classifications, caller identity, source-to-context certificates, immutable issuer binding, fee framing and native scheduler refinement are substantive unproved interfaces. Pending deposits are obligations, never already spendable reserve. The queue instantiation covers FA1.2/FA2; ticket ownership and FA2.1 adapter conversion need separate native resource proofs. This is a conditional composition theorem, not completed Octez collateral verification.

`MichelineRoundtrip.v` defines an independent Coq-side encoder and proves decoding its output reconstructs any finite raw tree, preserves an arbitrary trailing stream and is injective, given sufficient decoder fuel. It also computes the encoder/token-stream equality for all five imported source trees. This strengthens framing correctness beyond a Python visitor producing both expected representations; it does not prove the JSON-to-Coq import or native parser correspondence.

`SelfCallShape.v` checks the exact parameter types, outgoing lookup annotations and operation-construction sites in the five source trees. It supplies a small resolver model for interfaces with no named entrypoints and proves the incompatible lookup cases there, including arbitrary address entrypoints for ticket delivery. The ticket pool's `%paid_ticket` pair-field annotation is not itself a callable entrypoint; the native resolver registers nested entrypoints under `or`. Native entrypoint normalization/resolution, immutable address-to-code binding and operation sender provenance still require a bridge. These syntax/model facts do not discharge the FA backing theorems' `sender <> pool` premise.

Operation identity is separate from its erased VM payload in `CollateralCallTree.v`. Native `script_interpreter_defs.ml:716` assigns a fresh nonce to each transfer, even when its parameters and handle equal an earlier transfer. The queue therefore uses a generic nonce-bearing operation type and an explicit payload projection. Source certificates bind the ordered `map payload emitted` list; accounting folds every occurrence. The previous value-as-identity interface could not represent repeated equal payloads with distinct native nonces, although its conditional mathematical theorems remained valid. `QueueIdentityExamples.v` now proves two identical decoded FA1.2 deposits with distinct IDs and sufficient payer funds execute twice and credit two units. Reusing one nonce with any second payload rejects before that application and rolls back the earlier deposit. Native nonce allocation/bounds, payload projection and context refinement remain open.

`FA12ParsedCollateral.v` and `FA2ParsedCollateral.v` start from success of the complete parsed modeled program and initial represented live notes. They derive zero tez, the exact output and next state, decoded movements and the source-entry certificate, then the reserve/liability bound and backing after mathematical settlement. FA2's private/public classification, reachable map and withdrawal order are derived. No trace, output shape, certificate or desired collateral inequality is a premise. Complete original primitive frame specifications, note witness soundness/representation uniqueness, operation-field decoding and `sender <> pool` remain explicit. Actual native emitted operations still need an order/multiplicity-preserving payload link to these outputs, followed by issuer execution and the identity-aware queue refinement.

`TicketParsedCollateral.v` likewise starts from the complete parsed modeled call, initial represented notes and initial stored-quantity backing. It derives old/paid ticket identities, returned storage and operations, zero final credit and the quantity equation, then proves returned stored quantity backs the next notes. An additional returned-ticket ownership certificate yields the inventory bound; it asserts a matching fragment rather than a liability inequality. This is a conditional returned-storage result. Native ticket positivity, input/storage ownership separation, linearity, custody transfer and downstream ticket/adapter call-tree composition are still unproved.

`DeclarativeSourceTyping.v` supplies connected declarative stack-typing
derivations for all five complete imported source bodies and links them to
their parameter/storage declarations. Its source-specialized rules cover
the instruction forms used by these programs, including branches, loops,
map operations and ticket operations. The inference computation chooses
intermediate stack witnesses only; the Coq kernel checks explicit rule
applications. No rule accepts inference success as a typing premise.
These are derivations in an independent model. Equivalence to Octez's native
type admissibility, annotation normalization and typed IR remains open, as
does correspondence between either model and native execution.

`TypedVMSubset.v` proves a simulation between a type-indexed Coq stack
semantics and `FullVM_WIP` for arbitrary finite compositions of 15 pure
instruction forms. It also checks the exact FA1.2 `DUP; DUP; ABS` source
slice. Its types cover natural and signed integers, booleans, unit, pairs
and lists. They exclude tickets and context-dependent instructions. The
proof is between two models; it neither consumes native typed IR nor proves
an OCaml translation, gas behavior or full-contract execution correspondence.

`SaplingIntegerLift.v` proves that the source-derived input/output limits,
64-bit circuit note bounds and a signed public balance exclude wraparound
modulo the Jubjub subgroup order. Modular binding then implies the ordinary
integer balance equation and the existing note-liability transition. The
native specialization uses the actual public balance limit of
2,100,000,000,000,000 base units. Accepted-verifier witness extraction remains
an explicit idealized cryptographic/context hypothesis. The proof does not
verify native cryptography or FFI, membership, nullifier storage or context
refinement. `SAPLING_INTEGER_LIFT.md` and its evidence manifest record the
source review and exact boundaries.
